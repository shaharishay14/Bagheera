# Bagheera — GUI for PANTHER Model (MVP)

Project for Sheba Medical Center. Interface layer wrapping the PANTHER pathology model. Python backend (FastAPI) + React/JS + Tailwind frontend + SQL (SQLite for MVP).

## MVP Scope (4 features only)
1. **Inference submission page** — pathologist enters dataset path (TIFF) + num_clusters, POSTs `/api/v1/inference`.
2. **Annotations** — POST `/api/v1/annotations` with `{target_id, target_type, note}`.
3. **Job management** — FIFO queue, drag-and-drop reorder of `Queued` jobs, status polling via `/api/v1/jobs/{job_id}/status`. Locked while `Processing`.
4. **Tests** — under `/tests` folder with scripts + results + lessons-learned (detailed design section8, section9).

## PANTHER is MOCKED
No real model. Worker sleeps random 5–15s, writes fake prototypes JSON, transitions `Queued → Processing → Done` (or `Error` ~10%). Keep mock isolated in `backend/workers/mock_panther.py` so real model can swap in later.

## Architecture (per design §2)
- **Frontend** (React) ↔ **API** (FastAPI) ↔ **SQLite** ↔ **Worker** (background thread). API and Worker communicate ONLY via DB (loose coupling). API never does heavy work.

## Endpoints (design §2.3)
- `POST /api/v1/inference` → `{dataset_id, num_clusters}` → `{job_id, status:"Queued"}`
- `GET  /api/v1/jobs` → list all (for dashboard)
- `GET  /api/v1/jobs/{job_id}/status` → `{job_id, status, progress}`
- `PUT  /api/v1/jobs/reorder` → `{ordered_job_ids:[...]}` (Queued only, reject if any Processing)
- `POST /api/v1/annotations` → `{target_id, target_type, note}` → `{annotation_id, message}`
- `GET  /api/v1/visualization/{job_id}` → clusters + patch paths (mock)

## DB Tables (MVP subset)
- `jobs(id, dataset_id, num_clusters, status, priority, created_at, started_at, finished_at, error)`
- `annotations(id, target_id, target_type, note, created_at)`
- `clusters(id, job_id, label, patches_json)` (mock output)

Status enum: `Queued | Processing | Done | Error`. FIFO = `ORDER BY priority ASC, created_at ASC`. Reorder rewrites `priority`.

## Rules
- Every endpoint gets a pytest test. Queue FIFO + reorder + lock-while-processing MUST be tested (design §8 TC-01, TC-02).
- No hardcoded paths. Config via `.env`.
- Commit per feature, descriptive messages (design §7).
- Column/field names in design are placeholders — pick sensible ones, document in code.
- Consult `.claude/skills/{backend,frontend,database}/SKILL.md` before touching that layer.

## Out of Scope (MVP)
Auth, WSI viewer, semantic labels UI, real PANTHER, file uploads (path-only for now), H5/PT parsing.
